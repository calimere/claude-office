Procédure d'installation

Installer Claude Office

Un bureau 3D où l'équipe voit ses sessions Claude Code travailler. Chaque session devient un îlot ; chaque agent, quelqu'un à un bureau.

  • ● 💼 au travail
  • ● ❓ attend une réponse
  • ● ☕ au repos

Ce qui quitte ton poste

La question d'abord, parce que c'est la seule qui compte avant d'installer quoi que ce soit.

L'agent tourne sur ton PC. Il reçoit les événements bruts de Claude Code — prompts, commandes shell, chemins de fichiers — et les réduit à un statut avant que quoi que ce soit ne parte sur le réseau.

Ce que l'agent reçoit

{
  "session_id": "68746c1f-4c33-…",
  "cwd": "C:\dev\client-confidentiel\paie",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "rm -rf /srv/prod"
  },
  "tool_use_id": "toolu_01DXCt…"
}

Ce qui part réellement

{
  "v": 1,
  "machine": "remy-pc",
  "session": "68746c1f",
  "project": "paie",
  "event": "PreToolUse",
  "act": "term",
  "ref": "toolu_01DXCt…",
  "ts": 1793874184450
}

Ce qui ne part jamais

  • Le prompt. Jamais, sous aucune forme.
  • La commande shell, le nom de fichier, le motif de recherche.
  • Le chemin complet — seul le dernier segment sort : C:\dev\client-confidentiel\paie devient paie.
  • Le résumé d'une tâche déléguée. Seul le métier de l'agent sort (Explore, Plan) : c'est lui qui peuple l'open space.
  • Le nom d'un serveur MCP. mcp__…_Atlassian_MCP__… devient web, point.
  • Le message d'une demande de permission. On sait que tu es sollicité, pas sur quoi.

Ce qui sort d'un outil, c'est sa catégorie : read, type, term, web, plan, think, task. De quoi colorer un écran, pas de quoi savoir ce que tu fais.

Vérifiable

Cette liste n'est pas une promesse : node smoke-serveur.mjs rejoue des événements truffés de secrets et cherche chacun d'eux dans ce qui sort. Le test échoue si un seul passe.

Et rien n'est stocké

Aucune base de données, aucun journal d'activité. L'état vit en mémoire : on recharge la page, la pièce est vide, et elle se repeuple en moins de dix secondes à partir des postes connectés. La seule chose qui survit à un redémarrage, c'est la liste des métiers d'agents déjà vus — ce sont les employés permanents de l'open space.

À faire une seule fois

Monter le serveur

Une machine quelque part, que les postes peuvent joindre. Docker, deux commandes.

  1. Tirer un jeton et démarrer

    Les postes présentent ce jeton pour publier. Garde-le : sans lui, ils ne se connectent pas.

    Linux / macOS 
    export OFFICE_TOKEN=$(openssl rand -hex 16)
echo $OFFICE_TOKEN
docker compose up -d
    Windows · PowerShell 
    $env:OFFICE_TOKEN = -join ((1..32) | % { '{0:x}' -f (Get-Random -Max 16) })
echo $env:OFFICE_TOKEN
docker compose up -d

  2. Vérifier qu'il répond

    Terminal 
    curl http://localhost:4317/health

    Attendu : {"ok":true,"v":1,"machines":0}. Le bureau est sur http://<ip-du-serveur>:4317/, et cette page sur /install.html — c'est l'adresse à envoyer aux collègues.

  3. Si le serveur est sur Internet

    Sur un LAN, la page reste libre. Dès qu'elle sort, mets un reverse proxy TLS devant, remplis VIEW_PASSWORD, et ne publie pas le port 4317 directement.

Les réglages

VariableRôle
OFFICE_TOKENLe jeton des postes. Obligatoire. Laissé vide, le serveur en tire un neuf à chaque démarrage et les postes décrochent.
VIEW_PASSWORDMot de passe de la page. Vide = libre (correct sur un LAN). L'identifiant est VIEW_USER, par défaut office.
CITYVille de la météo. C'est le seul appel sortant du serveur, et il n'envoie que le nom de la ville.
OFFLINE_GRACEDélai avant de démonter les îlots d'un poste coupé brutalement. 20 s par défaut.

À faire sur chaque PC

Brancher un poste

Une archive à décompresser, et c'est fini. Rien à installer, aucune dépendance.

  1. Récupérer l'archive de son système

    claude-office-agent-windows-amd64.zip pour Windows, claude-office-agent-linux-amd64.tar.gz pour Linux (-arm64 sur ARM). Chacune contient l'exécutable, la page de la vue locale, et un LISEZMOI.txt.

  2. Windows : décompresser, double-cliquer

    lancer-agent.bat lit agent.cfg, enregistre la configuration dans %APPDATA%\claude-office\agent.json, installe les hooks, et démarre. Les fois suivantes, le double-clic suffit seul.

    Si l'archive n'est pas pré-remplie, ouvre agent.cfg et remplace les deux lignes par l'adresse du serveur et le jeton.

  3. Linux : un script, sans sudo

    Il pose tout dans le dossier personnel — exécutable, configuration en mode 600, hooks, et un service systemd utilisateur qui démarre avec la session. ./installer.sh --desinstaller fait le chemin inverse.

    Terminal 
    tar xzf claude-office-agent-linux-amd64.tar.gz
cd claude-office-agent && ./installer.sh http://ip-du-serveur:4317 LE_JETON

  4. Relancer claude

    Ton îlot apparaît dans le bureau. Il n'y a rien d'autre à faire — mais il faut bien relancer : une session déjà ouverte garde les hooks qu'elle avait au démarrage, et ne remontera rien.

À la main, si tu préfères

L'exécutable seul suffit : claude-office-agent -server http://ip-du-serveur:4317 -token LE_JETON -save -hooks. -save écrit la configuration, -hooks fusionne les huit hooks dans ~/.claude/settings.json sans toucher à ceux qui s'y trouvent déjà — et ne réécrit rien s'ils sont tous là, donc on peut le passer à chaque lancement. Par défaut l'îlot porte le nom de la machine ; -machine "Bureau de Rémy" pour en choisir un autre.

En ligne, mais zéro session ?

C'est toujours les hooks. L'agent se connecte parfaitement sans eux : le poste apparaît dans le bureau, en ligne, et ne remonte rien. Vérifie ~/.claude/settings.json, puis relance claude.

Deux bureaux, pas un

L'agent sert aussi une vue locale sur http://127.0.0.1:4317/, avec tout le détail : noms de fichiers, commandes, prompts. C'est ta machine, ça n'en sort pas. Seul ce qui part vers le serveur est réduit à un statut. Pose index.html à côté de l'exécutable pour que cette vue fonctionne.

Vérifier que ça marche

Dans cet ordre : le poste, puis le serveur.

Sur le poste

Navigateur ou curl 
curl http://127.0.0.1:4317/status

La clé qui compte est flotte.en_ligne. Si elle vaut false, flotte.derniere_erreur nomme le problème.

Sur le serveur

Navigateur ou curl 
curl http://ip-du-serveur:4317/sessions

Tu y vois les postes connectés, leurs sessions et les sous-agents au travail. C'est aussi la preuve la plus directe de ce que le serveur sait — et de tout ce qu'il ignore.

Comparer les deux vues, côte à côte

Le test qui répond vraiment à « qu'est-ce que mes collègues voient ». Sur une seule machine, deux terminaux — le serveur prend 4318, parce que l'agent occupe 4317, là où pointent les hooks.

Terminal 1 · le serveur 
$env:OFFICE_TOKEN="test123"; $env:PORT="4318"; node server.js
Terminal 2 · l'agent 
.\agent\claude-office-agent.exe -server http://127.0.0.1:4318 -token test123

Puis ouvre les deux pages en vis-à-vis et travaille normalement. À gauche « 📖 lit order.service.ts », à droite « 🔎 cherche ».

http://localhost:4317/Vue locale — le détail complet, qui reste sur ta machine
http://localhost:4318/Vue flotte — exactement ce que voient les autres

Si ça ne marche pas

Les quatre pannes qu'on rencontre réellement.

SymptômeCause et remède
Mon îlot n'apparaît pas, et /status dit en_ligne: false Lis derniere_erreur. « a répondu 401 » = jeton refusé ou nom de poste invalide. Sinon, c'est le serveur qui n'est pas joignable : pare-feu, mauvaise IP.
/status dit en_ligne: true, mais sessions: 0 Les hooks ne sont pas installés. Vérifie que le bloc hooks est bien dans ~/.claude/settings.json, et relance claude.
« écoute locale impossible sur 127.0.0.1:4317 » Le port est déjà pris — un server.js ou un autre agent tourne déjà. Arrête-le, ou donne un autre port à l'agent avec -port.
Un poste éteint reste affiché un moment C'est voulu. Une coupure brutale laisse 20 s de grâce, pour qu'un hoquet de wifi ne fasse pas disparaître puis réapparaître tout le plateau. Un arrêt propre de l'agent, lui, démonte ses îlots tout de suite.
